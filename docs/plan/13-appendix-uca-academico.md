## E. IMPLICATIONS FOR THE PRODUCT

1. Email verification is feasible on a single domain. Students and docentes both receive @uca.edu.ar accounts (Microsoft 365 identity). Verify with a magic link / OTP to any address ending in @uca.edu.ar. Caveat: since staff share the domain, domain-match alone does not prove "student" status; combine with self-declared carrera + cohort, or optionally ask for a Microsoft OAuth login which proves live account ownership. No separate student subdomain was found, so do not build for @alumnos.uca.edu.ar.
2. Catalog size estimate for sede Rosario: 1 sede, 3 facultades, roughly 10-14 carreras de grado/pregrado. A full materia catalog for the two flagship carreras is ~52 core materias (Abogacia) + 57 slots (Contador Publico) + ~40 optativas; loading all Rosario carreras would likely land in the 300-500 materia range. Seeding the two verified plans (sections C.4/C.5) covers the largest expected user segments (Derecho and Economicas) on day one.
3. Plan versioning matters: Abogacia has planes 2013 and 2020 coexisting; Contador Publico is Plan 2017. The materias table should carry a plan (or plan_version) column from the start so students of different cohorts see the right grid.
4. Calendar-driven features (turno de finales reminders, inscripcion alerts) can be seeded from section D, but dates vary by facultad by a few days and "podrian sufrir modificaciones" per UCA's own disclaimer — model calendar entries per facultad per year, editable.
5. The uca.edu.ar site is a JS SPA; scraping for automatic catalog sync is unreliable. The stable machine-readable surface is wadmin.uca.edu.ar PDFs. Plan for manual/curated catalog updates once per cuatrimestre rather than live scraping.
